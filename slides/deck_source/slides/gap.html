Both our numbers are below the paper's, and the mimetic number by about twice as much. Position embedding scale: the paper's ImageNet section says it used the CIFAR-10 hyperparameters "with a position embedding scale of 1", which suggests CIFAR-10 used another scale. Mimetic init works through the position embeddings, so a wrong scale would hurt mimetic more than base, which matched our pattern. We added a --pos-scale argument (it multiplies the sinusoidal buffer once in the model's __init__) and ran mimetic with scale 2. It ended at 88.59, 0.28 below scale 1. So this was not the cause. Remaining causes: the schedule, augmentation strengths, crop and flip, MLP ratio and regularization are not in the paper; each can move CIFAR-10 accuracy by tenths of a point. Many ViT code bases use truncated normal with std 0.02 for linear layers; we use the PyTorch default. And with one seed, part of each gap may be chance; the paper does not say how many runs it averaged. Ruled out: accuracy was flat over the last ten epochs; the init self-test shows +0.39 and -0.40 diagonals; scaled_dot_product_attention matches the hand-written formula to below 1e-6; best epoch is at most 0.1 above epoch 100. Mixed precision is unlikely to matter (smooth loss) but we did not run float32.
